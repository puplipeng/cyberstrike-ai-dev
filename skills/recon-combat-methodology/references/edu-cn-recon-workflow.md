# .edu.cn 目标信息收集实战流程

## 案例经验：成都艺术职业大学

源自 2026-06-24 实战，以下流程可复用于类似 .edu.cn 教育目标。

## 并行派发策略

信息收集阶段使用 `delegate_task` 同时派发 3 个子任务：

```
委托 1：端口扫描 + 指纹识别（nmap/curl/WhatWeb）
委托 2：子域名枚举 + ICP 备案 + whois（DNS/搜索引擎/子域名爆破）
委托 3：测绘平台查询（Quake API — 主域 + IP + 旧域）
```

并行收集完成后统一汇总写入飞书文档。

## DNS 泛解析（Wildcard）的处理

.edu.cn 目标大量使用 DNS 泛解析 `*.edu.cn` → 同一 IP：

- 泛解析的子域名数量 250+ 很常见
- 大多数子域名无实际服务（返回 502 / connection refused）
- 需通过 HTTP 响应或测绘平台区分「有实际服务」和「仅 DNS 解析」的子域
- 测绘平台（Quake/Fofa）是区分泛解析子域名是否真实的有效工具

## WAF 感知扫描

教育类目标常部署 WAF 或速率限制：
- 首次 nmap 扫描正常识别开放端口
- 多次扫描后 WAF 触发，端口状态变 closed/filtered
- 解法：限制扫描频率 + 使用 Quake 测绘做被动补充

## 三线部署架构

中大型高校常见三线架构：
- 中国电信（125.71.x.x）→ 主站 + SSLVPN
- CERNET 教育网（202.115.x.x）→ DNS 服务
- 中国移动（183.223.x.x）→ 旧域名 / 备份线路

旧域名和历史域名（曾用校名）可能仍在运行，是常见忽视的攻击面。

## .edu.cn 备案/whois 限制

- 不在公开 ICP 备案 API 范围内
- whois 查询 CNNIC → "Out of this registry"
- whois.edu.cn → 超时
- 依赖测绘平台或搜索引擎获取组织信息

## 单次探测发现的攻击面举例

当发现以下资产时，按优先级排序：

1. **SSLVPN 设备（锐捷/深信服/H3C）** — 历史漏洞多，优先级最高
2. **文章/新闻系统 IDOR** — 连续 ID 遍历
3. **融合门户/一站式服务门户** — 统一认证入口
4. **论文提交平台** — 文件上传功能场景
5. **教务系统** — URL 模式 `jw` / `jwc` / `ehall`
